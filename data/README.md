# Data Pipeline + Cleaning

**Owner:** Data pipeline team (Jasmine)  
**Study area:** Indonesia  
**Source:** [NASA FIRMS](https://firms.modaps.eosdis.nasa.gov/)

This directory documents the historical and near-real-time MODIS/VIIRS hotspot processing workflow for Ignisensing Analytics. The canonical data contract is [`SCHEMA.md`](SCHEMA.md); David's filtering rationale is in [`../docs/data-quality-filters.md`](../docs/data-quality-filters.md). The files produced by this pipeline are **satellite detections**, not counts of distinct wildfire events.

## Raw data

Eight archive and NRT downloads were obtained for Indonesia (through November 2026). The initial raw-data audit covered **8,898,888** detections before the updated team filters.

| Product | Raw detections | Initial source coverage |
|---|---:|---|
| MODIS Terra/Aqua | 1,696,288 | 2000–2026 |
| VIIRS S-NPP | 4,140,587 | 2012–2026 |
| VIIRS NOAA-20 | 1,963,134 | 2018–2026 |
| VIIRS NOAA-21 | 1,098,879 | 2023–2026 |
| **Total** | **8,898,888** | |

Both standard processed archive files (identified as `SP` in the output) and near-real-time files (`NRT`) are read. NOAA-20/21 source files are retained in `raw/` but **excluded** from the current processed outputs by the satellite filter. Raw CSVs are never overwritten.

The initial raw-file checks found no missing fields, invalid dates/times or coordinates, or exact duplicates **within each file**. This does not establish complete satellite coverage or absence of cross-file overlaps.

## Run the pipeline

From the repository root, with Python and `pandas` and `numpy` installed:

```bash
python data/clean_data.py
python data/verify_data.py
```

The scripts find their folders from their own location, so they also work when run from inside `data/`.

`clean_data.py` processes input in 100,000-row chunks and replaces the three processed output CSVs only after successful completion. It reads `data/fire_filter_config.json`. `verify_data.py` checks the generated outputs; it does not independently validate the scientific appropriateness of the filtering parameters.

A FIRMS MAP_KEY is optional for **manual downloads** of the raw data. If using the FIRMS API separately, never commit API keys or `.env` credentials.

## Selection and confidence filters

These are applied **before** the records are exported and before the static-source mask is constructed.

| Criterion | MODIS | VIIRS |
|---|---|---|
| Satellites | Terra (`T`) and Aqua (`A`) | S-NPP (`N`) only |
| Years | 2003 onward | 2012 onward |
| Confidence retained | Numeric `>= 30` | `n` and `h` |
| Historical `type` | Retained as `fire_type` | Retained as `fire_type` |

The `confidence` output is standardized to `low`, `nominal` or `high` (MODIS 0–29 / 30–79 / 80–100; VIIRS `l` / `n` / `h`). The original value is preserved as `confidence_raw` for robustness checks. Although `low` remains a valid schema category, the current selection filters exclude low-confidence detections.

**Fire type is *not* used to delete archive rows from `hotspots.csv`.** It determines the vegetation flag instead. NRT files lack a `type` column, so applying `type == 0` directly to NRT would incorrectly remove recent data.

## Non-vegetation and static-source logic

The pipeline builds a list of potentially persistent non-vegetation heat-source cells from filtered **SP/archive** detections with FIRMS `type` 1 (volcano) or 2 (other static land source).

1. Divide the study area into **0.01° latitude/longitude cells**.
2. For each cell, collect the **distinct calendar months** with a qualifying archive detection.
3. Mark a cell as static-source-associated if detections occurred in **at least three different months**.
4. Export those cell centres in `processed/static_source_cells.csv`.
5. Set `static_source_mask` to `1` for **both SP and NRT detections** in these cells, otherwise `0`.

`vegetation_flag` is always either `0` or `1`:

| Source | Rule |
|---|---|
| SP/archive | `1` when `fire_type == 0`; otherwise `0` |
| NRT | `0` when `static_source_mask == 1`; otherwise `1` |

All retained detections remain in `hotspots.csv`, including non-vegetation-flagged rows. Downstream counts and maps should use **`vegetation_flag == 1`**. The flag is a filtering convention, not independent proof that each detection represents a vegetation fire.

Current config (`data/fire_filter_config.json`):

```json
{
  "grid_size_degrees": 0.01,
  "minimum_archive_months": 3,
  "static_source_types": [1, 2],
  "apply_mask": true
}
```

Changing these settings requires rerunning the pipeline and verifying the new outputs.

## Output 1: `processed/hotspots.csv`

**5,337,627 filtered hotspot records**, in the exact shared-schema column order:

| Column | Meaning |
|---|---|
| `date`, `time` | UTC acquisition date (`YYYY-MM-DD`) and 4-digit `HHMM` |
| `lat`, `lon` | Original detection coordinates |
| `sensor` | `MODIS` or `VIIRS` |
| `satellite` | `T`, `A` or `N` |
| `confidence` | Standardized confidence label |
| `confidence_raw` | Original numeric MODIS confidence or VIIRS `n`/`h` |
| `frp` | Fire radiative power, MW |
| `daynight` | `D` or `N` |
| `source` | `SP` (archive) or `NRT` |
| `fire_type` | Original archive type `0`–`3`; blank for NRT |
| `static_source_mask` | Integer `1`/`0`, applied to SP and NRT |
| `vegetation_flag` | Integer `1`/`0`, always present; **filter on this** |

FIRMS archive fire types: `0` = presumed vegetation fire, `1` = active volcano, `2` = other static land source, `3` = offshore detection.

## Output 2: `processed/cell_monthly_counts.csv`

**2,459,298 cell-month-satellite records**, of which **2,067,267 have `count = 0`**.

This ML training dataset aggregates **only `vegetation_flag == 1`** detections on a **0.25° × 0.25°** grid. It is not the static-source masking grid.

| Column | Meaning |
|---|---|
| `cell_lat`, `cell_lon` | Centre of the 0.25° grid cell |
| `year`, `month` | Calendar month |
| `sensor`, `satellite` | `MODIS`/`T`, `MODIS`/`A` or `VIIRS`/`N` |
| `count` | Number of vegetation-flagged satellite detections |
| `mean_frp` | Mean FRP for detections; blank if count is zero |

Cell centres use `floor(lat / 0.25) * 0.25 + 0.125` and the analogous longitude formula. Every cell containing at least one vegetation-flagged detection in the observed dataset gets a row for **each satellite and every eligible month**: Terra/Aqua from January 2003, and S-NPP from January 2012, through the latest observed month. Missing fires appear as `count = 0`, not as missing records.

**Interpretation:** A zero indicates no retained detections in that cell/month/satellite. It does not necessarily imply an absence of actual fires or complete observation coverage.

## Output 3: `processed/static_source_cells.csv`

**3,520 static-source cells**, stored as `cell_lat`, `cell_lon` (0.01° cell centres). This is a supporting reference file, rather than a third main analysis dataset. It can be reused when classifying new NRT detections with the same mask configuration.

## Limitations and interpretation

- A detection is not a unique physical fire; multiple satellites and overpasses may register the same event.
- MODIS and VIIRS have different sensitivity, resolution and temporal coverage; their raw counts are **not interchangeable**. Harmonization is handled by the ML team.
- `vegetation_flag` is partly inferred for NRT; real vegetation fires near volcanoes or industrial heat sources can be flagged out.
- The static mask depends on the complete available archive, including observations later than some earlier NRT detections. **Do not use it as a time-causal historical predictive feature without rebuilding it using only past information.**
- Latitude/longitude cells vary in actual ground area with latitude.
- Archive and NRT products may overlap or be updated; these files reflect the available inputs and stated filters, not a completeness guarantee.
- Zero-filled ML counts are not evidence of continuous satellite observation.
- These data are appropriate for historical analysis and demonstrations, not operational emergency-response decisions.
